# BallerWatch 8.9.0 — release checkpoints

A release is complete only when every safety gate below is verified. Source
merge, GitHub Release publication, Worker deployment and Pages activation are
separate states: never conflate them.

## Checkpoint A — UI and card design
- [x] One canonical ::before waterfall implementation shared by match/standings
- [x] Match action button hit-zone remains separate from full-height visual
- [x] Shared h2/kicker/meta tokens, including the match-date heading
- [x] Bottom-pinned standings footers (including no-results divisions)
- [x] Shared bw-card-frame / bw-card-title / bw-card-footer entry points
- [x] Permanent card design specification in docs/CARD-DESIGN-SYSTEM.md
- [ ] Static regression tests pass on exact source commit

## Checkpoint B — scouting forward tests
- [x] Deterministic precomputed three-outcome predictor and candidate grid
- [x] Strict previous-season -> next-season evaluation with no current-season leakage
- [x] Actual candidate and baseline compared with Brier (lower is better)
- [x] Insufficient history, thin evidence or worse measured results retains baseline
- [x] Model weights and aggregate diagnostics embedded in hourly encrypted index
- [x] No live training/calculation on public card/AI read endpoints
- [ ] Full synthetic regression passes on exact source commit
- [ ] Production historical archive run reports actual fold size/lift; do not
      claim improvement if no significant improvement is measured

## Checkpoint C — documentation and release
- [x] Short README release summary, older releases only linked
- [x] Version ledger and cache keys updated for v8.9.0
- [ ] Validate code, privacy audit and safe AI QA pass
- [ ] Pull request passed and merged to main
- [ ] GitHub v8.9.0 release published from exact validated ledger commit
- [ ] Production branch matches exact release commit
- [ ] Worker live health/security and GitHub Pages deployment pass

## Checkpoint D — stale Git branches
- [ ] Fetch current remote branch list and compare branch heads to main
- [ ] Delete only merged, clearly disposable stale working branches
- [ ] Preserve main, production, runtime-state and all unmerged branches
- [ ] Record protected/skipped branches; no silent loss of work

The periodic index is free and offline deterministic; outside generative-AI
providers are deliberately not used for fitting numerical weights. An LLM
may summarize aggregate diagnostics, but it must never see private runtime
state or invent confidence levels. Continue using the existing six-hour
privacy-safe review and exact-sha release gates.
