# BallerWatch cinematic app and V2 retirement

Current product release: **11.0.0**. The cinematic frontend is now the canonical app at **https://vudh1.github.io/ballerwatch/**. The root manifest ID, start URL, scope and installation identity remain `/ballerwatch/`; existing V1 Home Screen installs update to the new presentation.

## Route migration and feature parity

`/v2/` is a deprecated redirect, preserving query strings and fragments. The small redirect document has a link and timed fallback if JavaScript is unavailable. Its legacy manifest and narrow worker remain available for existing installs/push subscriptions. Both workers send notification clicks to the root. An old V2 install needs an online visit to acquire the root worker; after that, old-route launches redirect to the cached root even offline. No backend endpoint, account, runtime-state branch, RSVP, Calendar source or watcher is moved or duplicated.

The root HTML retains every original functional controller ID except the retired launch/version-selector controls. Tests compare against `tests/frontend/fixtures/v1-8.14.1.html`, including exact match/calendar/standings feed markup and computed card styles. The original standalone status-area glass is retained. Both presentations always used the same `app.js`; all account/admin actions, rosters, RSVP, calendar, standings/scouting/forecasts/history, field sharing, contextual AI, Inbox/filters/read state, Web Push/badges, music and personalization remain on that controller.

The canonical app retains original root preference keys. `lib/experience.js` copies a retired V2 presentation value only if the corresponding original key is absent, without erasing either value. Shared authentication and notification keys are unchanged. No production user mutations are used for validation.

## Animation and interaction

The sequence is a two-second V1-style branded launch, a native-scroll soccer feature tour, then the original cards. The shooter wears 10, short sleeves and a captain band, with a continuous neck/collar. Equal-length keeper arms follow a late dive; the faster, flatter shot reaches goal before the save extends. The intro’s Skip intro action jumps to the card reveal; the brand loading screen no longer has a skip button while keeping this document’s upward rewind. A subsequent session entry and reduced motion may enter directly. When the intro document is reloaded, its logical main-page offset is restored instead of the obsolete intro height. Six borderless feature captions sit between the stadium background and transparent foreground action, so the ball and diving keeper cross in front of the words. There are no scroll/rewind instructions or replay/version controls in Settings.

The stadium audience and six localized camera flashes sit below captions. Flash opacity is a deterministic function of scroll (`cameraFlash`), with no autoplay timer or full-screen strobe. Reverse scrolling reproduces camera flashes, shot, keeper and text. Reduced motion bypasses the launch/hero. Failed artwork/modules fail open, with a 2.5-second prepaint watchdog. Data/session startup remains independent.

The single badged AI launcher takes exactly the same opacity as the card feed and appears only as the app becomes interactive. AI / Settings / Notifications navigation lives inside the three connected modal panes, preserving existing controller hooks and content. No detached header controls remain. Scene hit testing turns off at reveal start and the launcher remains outside the inert feed. Notification preference checks stay adjacent to labels.

The sticky stage covers `100dvh`, with `svh` scroll travel and `vh` fallbacks. Its opaque scene-colored background prevents footer leaks before the reveal. Matching card overlap and synchronized SVG viewports/camera transforms keep portrait/landscape resizing coherent. Safe areas protect controls and cards. Hardware iPhone installation, audio, real push and VoiceOver remain manual checks; automated tests cover Chromium/WebKit mobile and standalone emulation without production mutations.

## Source and tuning

The canonical document is `frontend/web/index.html`; the retained `v2/` directory contains cinematic modules/artwork and the retired route redirect, not a second application. `scene-config.mjs` owns the six feature stories, 2000 ms launch, 3.2-screen travel, pure ball/keeper poses and camera-flash moments. `timeline.js` owns requested scroll/resize frames and shared background/action cameras. `v2/styles.css` styles only the cinematic/reveal/control layers, inheriting original cards from root `styles.css`. `v2/app.js` initializes the timeline and scoped frontend-cache control; it has no API client or polling loop.

The root worker precaches all canonical assets plus the old redirect. Its `ballerwatch-v9-1-1-shell` cache and original device cache remain separate from the legacy `ballerwatch-v2-v9-1-1-shell` and legacy device state. Each worker removes only its own obsolete shell caches. Settings → Offline files clears only the canonical frontend shell, preserving legacy/device/auth state. Reconnect before the next offline startup after explicitly clearing frontend files. Missing scripts never receive HTML. Workers never cache remote API or authenticated responses.
